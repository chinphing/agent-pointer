# 两张图的分工

本次提供两张图。

- **图一（小图）**：以候选位置为中心从屏幕上裁剪的区域，目标在该图中**较大、较清晰**。
- **图二（整屏）**：**完整的屏幕截图**，未作裁剪。目标在该图中较小，但**整个界面均在画面内**。

两张图中均有**红色十字星**，**交点即交付坐标**。

## 图二的十字臂贯穿整个画面

图二的十字并非小十字，**四条臂延伸至画面边缘**：

- **竖线**自画面顶端贯穿至底端
- **横线**自画面左端贯穿至右端

**其作用在于使远处的参照物与交点连成一条直线。** 交点在图二中仅占数个像素，难以辨识；而直线长达上千像素，辨识度高。

## 图二可确认的内容

**图二并非仅为「读取行列标签」而存在。** 它能回答的是**「交点在该界面中处于什么位置」**，具体读法取决于界面形态：

| 界面形态 | 图二的用法 |
|---|---|
| **带行标 / 列标**（表格、数独、数据表） | 沿直线行至边缘，读取所对应的标签 |
| **有序列但无标签**（卡片网格、列表、工具栏按钮、缩略图、标签页） | 自起点依序计数确定其序号；或观察其是否与某个已知元素处于同一行 / 同一列 |
| **自由布局**（画布、浮动面板、对话框） | 仅观察对齐关系：是否与某个元素处于同一水平线 / 垂直线上，落在哪个区域范围内 |

**没有印着数字的标签，并不等于无法定位。** 「第 3 张卡片」与「C 列」属于同一类信息 —— 均为「在序列中的位置」。

## 分工

**图二用于观察远处。** 交点属于哪一行 / 哪一列 / 第几个 / 与什么对齐 —— 这些信息在图一中无法获得，因为图一只裁剪了局部。**仅当描述要求此类信息时才需查看图二。**

**图一用于观察近处。** 交点压在什么上面、格子内 / 按钮上写的是什么、是否压到边线、紧邻的是什么 —— 图一中目标最大，唯有它能够准确呈现。

**图二不能用于判定「交点是否在目标内」** —— 该图中目标过小，交点相对目标的位置无法体现精度。判定交点压住了什么，仅依据图一。

**两张图对同一位置的说法不一致时**，应先怀疑自身读数有误并重新核对 —— 但不得直接采信描述中的数值。
