# 定时任务

[English](../../en/user/scheduled-tasks.md) | 简体中文

定时任务让**智能体按计划自己跑一轮对话** —— 到点了它自己执行提示词，跑完还能把结果推到 IM。

它不是「跑一条命令」的 cron：每一次触发都是一次完整的对话回合，所以提示词里可以要求它查资料、读文件、调工具，再用自然语言汇报。

```
调度器（每分钟左右检查一次）
   └─ 到点 → 在该任务自己的会话里跑一轮
        ├─ 会话 id：cron:{任务 id}:{日期}   ← 「查看会话」看的就是它
        └─ 勾了推送 → 把这一轮的最终回复发到所选 IM 渠道
```

## 两个入口

| 你想 | 去哪 |
| --- | --- |
| 看着界面建、看着列表管 | **设置 → 自动化 → 定时任务** |
| 顺手说一句 | 直接在对话里说「每天早上 9 点帮我看一下 XX」，助手会用 `cron_job` 工具建好 |

对话里的 `cron_job` 工具支持 **创建 / 列出 / 启用 / 停用 / 删除** 五个动作。建完之后，界面和工具是同一份数据 —— 在设置里能看到助手建的任务，也能让它列出你在界面上建的任务。

## 新建一个定时任务

**设置 → 自动化 → 定时任务 → 新建**

| 字段 | 说明 |
| --- | --- |
| **名称** | 列表里显示的名字，例如「每日日报」 |
| **智能体** | 用哪个执行智能体跑（通用助手 / 氛围编程 / 电脑操控），默认通用助手 |
| **触发提示词** | 每次触发时发给智能体的提示词。**这是任务的主体**，写清楚要它做什么、怎么汇报 |
| **调度** | 用下面的选择器选频率 |
| **推送到 IM** | 勾上后，从已绑定的通道里多选；不勾就只在会话里留结果 |

调度选择器覆盖了绝大多数场景，不用手写表达式：

| 选择器里的选项 | 生成的表达式 |
| --- | --- |
| 一次延迟 | `30m` / `2h` / `1d` |
| 指定时间一次 | `2026-07-22T09:00:00` |
| 每分钟 | `0 * * * * *` |
| 每 N 分钟 | `0 */5 * * * *` |
| 每 N 小时 | `0 0 */2 * * *` |
| 每天 | `0 30 9 * * *`（9:30） |
| 每周 | `0 30 9 * * 1`（周一 9:30） |
| 每月 | `0 0 9 1 * *`（每月 1 日 9:00） |
| 自定义 | 原样使用你写的字符串 |

### 时间还能怎么写

在对话里让助手建任务时，`schedule` 字段支持这些写法：

| 写法 | 例子 | 含义 |
| --- | --- | --- |
| 相对量 | `30m`、`2h`、`1d` | 从现在起 30 分钟 / 2 小时 / 1 天，跑一次 |
| ISO 时间 | `2026-07-22T09:00:00` | 指定本地时间跑一次（也接受 `2026-07-22 09:00:00`） |
| 每天 | `daily@9:30`、`每天 09:00` | 每天固定时间 |
| 每周 | `weekly@1@9:30`、`每周一 9:30` | 0=周日 … 6=周六 |
| 每月 | `monthly@1@9:00`、`每月1日 9:00` | 每月固定日期 |
| 每分钟 / 每 N 分钟 | `every_minute`、`every_5_minutes`、`每10分钟` | 周期执行 |
| 每 N 小时 | `every_2_hours`、`每2小时` | 周期执行 |
| **6 段 cron** | `0 30 9 * * *` | 直接写表达式 |

> **6 段 cron 的第一个字段必须是 `0`。** Pointer 只接受「秒位为 0」的 6 段表达式；`@daily` 这类 cron 宏、以及常见的 5 段 cron（`30 9 * * *`）都不认。写不出来就用上面的友好写法。

## 任务列表

每一行从上到下：

| 位置 | 内容 |
| --- | --- |
| 左侧开关 | 悬停提示「已启用（点击停用）」/「已停用（点击启用）」 |
| 主行 | `名称 · 智能体 · 调度`，勾了推送再追加投递渠道 |
| 右侧 | 「下次 {时间}」 |
| 操作 | 「修改投递目标」（没设过时显示「设置投递目标」）、「查看会话」、删除 |
| 异常 | 投递失败时追加一行「投递失败：{原因}」 |

删除是**两步**的：点一次垃圾桶，按钮变红、标题变成「确认删除」，旁边出现「取消」；再点一次才真的删。

## 每次运行都是一个会话

任务每触发一次，就在自己的会话里跑一轮。会话 id 是 `cron:{任务 id}:{日期}` —— 所以同一个任务不同天的记录是分开的。

点行里的「**查看会话**」会直接打开那次运行的会话，能看到它当时想了什么、调了什么工具。任务还没触发过时按钮是灰的，提示「任务尚未触发，暂无会话可查看」。

## 推送到 IM

勾「推送到 IM」并选通道后，每轮结束会把**最终回复**发到所选渠道。

- 通道必须**已经绑定**：需要你先在那个通道里私聊过 Pointer
- 一个通道对应**最近一次私聊 Pointer 的人**
- 想跳过某一次的推送，让它在回复里带上 `[SILENT]`

## 调度器本身

调度由应用里的调度器负责，**默认就是开的**，没有界面开关。要关掉它只能用环境变量：

```bash
POINTER_SCHEDULER_ENABLED=0
```

服务端和桌面端都是默认开启；关掉之后所有定时任务都不再触发（任务本身还在）。

调度器**每分钟左右**检查一次，所以一次性任务的实际触发时间可能比设定值晚不到一分钟。

一次性任务跑完会**软完成**：它不会被删除（保留历史），但会变成停用状态，也不能重新启用。

## 常见问题

**「请填写名称」/「请填写调度」/「请填写触发提示词」**

新建表单里这三项都要填。

**「请选择至少一个推送通道」**

勾了「推送到 IM」但一个通道都没选。

**「暂无已启用的 IM 通道。」/「请先在对应通道私聊 Pointer，完成绑定后再选。」**

还没有可用通道。先去 **设置 → 连接** 启用一个通道，并在那个通道里私聊一次 Pointer 完成绑定。

**「一次性任务不可重新启用，请新建」**

一次性任务跑过就软完成了，历史保留但不再触发。要再跑一次就新建一个。

**「该任务尚未触发，暂无专属会话可查看」**

任务还没到点跑过，所以没有会话。等它触发一次，或者先检查开关是不是停用了。

**助手说时间格式不认识**

把原文换成友好写法即可。解析失败时它给出的示例是：`30m`、`2026-07-22T09:00:00`、`daily@9:30`、`every_5_minutes`、`0 30 9 * * *`。

**到点了没跑**

依次看三处：任务的启用开关、调度器有没有被 `POINTER_SCHEDULER_ENABLED=0` 关掉、以及是不是一次性任务已经跑过（软完成）。
