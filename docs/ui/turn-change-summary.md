# 轮次修改摘要（挂在 turn 页脚）

把文件变更从输入框上方挪到**每一轮对话结尾**。
视觉上跟「工作耗时」同一层级：过程备注，不是第二条助手气泡。

基线存储与 Review API 见
[`../developer/turn-file-baseline-review.md`](../developer/turn-file-baseline-review.md)。

## 位置

每个 user-anchored turn（`turn.id` = lead 用户消息 id）页脚，顺序固定：

1. 用户问题
2. 过程 / 任务板 / 助手回复（可折叠）
3. 耗时条（有隐藏过程时）
4. **修改摘要**（该轮有成功写文件才出现）
5. 下一轮用户消息

过程折叠时摘要仍在。输入框上方不再挂「本轮修改」。

挂在 `MessageList` 虚拟行内部，和消息同一 `.chat-column`。
不要贴 Composer，不要做成助手气泡。
不要重排用户问题、过程、任务板、助手回复或耗时条；
只在该轮现有内容后面挂载摘要。

## 外观

与助手正文同一 `px-3` 左边距，左缘对齐「测试要点」等正文。
小卡片：`width: max-content`，约 15.5–22rem，不占满对话列。
圆角 `rounded-lg`、细描边、无阴影、`bg-card` 浅底（与对话背景区分）。

**标题行**

- 高约 34px，左右内边距 12px
- 左：文件图标 + `修改了 N 个文件`（13px，`text-muted`）
- 文案后：该轮合计 `+n` / `-n`（有统计才显示）
- 右：chevron（展开旋转 180°）

**仅 1 个文件**

- 文案：`修改了 Login.vue` + 合计 `+/-`
- 点击标题打开该轮 diff，不展开列表

**2 个文件**

- 默认展开列表；用户收起后本会话内记住

**文件列表（展开）**

- 与标题之间 1px 分隔；行与行之间同样分隔
- 左：相对路径（11px mono）；右：该文件 `+n` / `-n`
- 行高约 34px；超过 6 个文件再滚，最多约 12rem
- 点击行打开该轮该文件的 Review
- 3 个及以上文件默认收起，点标题展开

进行中：文案仍是 `修改了 N 个文件`，N 随成功写入增加，不写「正在修改」。

无成功 `file_edit` / `file_write`：整块不渲染。

## 交互

| 操作 | 行为 |
|------|------|
| 点标题（多文件） | 只展开列表，不打开工作区 |
| 点文件行 / 单文件标题 | `openTurnDiff({ conversationId, turnId, path })` |
| 展开列表 | 该虚拟行 `resizeTurnRow`，避免重叠 |
| 无工作区 | 不打开；debug 打 warn |

展开状态按 `turnId` 记在 `MessageList` 内存，不落盘。切会话清空。

## 数据

- 列表：该轮（含子 Agent）成功写文件工具，按路径去重
- `+/-`：该轮工具结果统计，表示「这一轮动了多少」
- 打开 Review：左侧 = 本轮基线；右侧 = **之后同一路径的下一份基线**，没有则对比磁盘
- 查找：只 `exists` 后续有基线的轮次目录，命中即停，不扫对话正文

列表能随消息持久化看到。历史轮打开 diff 时，右侧不再被更后面的手改/再编辑拖走（最后一次改该文件的轮次仍对比磁盘）。

## 文案

| 场景 | 文案 |
|------|------|
| 多文件收起 | 修改了 N 个文件 +n -n |
| 单文件 | 修改了 {文件名} |
| Review Tab | 文件名；副标题不写「本轮」 |
| 基线缺失 | 沿用现有 Review 空态，摘要列表仍显示 |

不要用「本轮修改」（挂在历史轮会歧义）。

## 跨端

桌面 / Web 同一组件。移动端同样页脚一行，展开列表不要撑破对话列。

## 不做

- 不在输入框上方再留最新一轮副本
- 不和右侧 Git「变更文件」合并
- 不在每轮结束再存一份全文（用下一轮同路径基线当「改完」）
