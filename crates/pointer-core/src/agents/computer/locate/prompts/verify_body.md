# 校验任务

{intro}

## 目标

判一件事：**十字星所在的位置，能不能作为点击描述说的那个元素或区域的落点。**

换句话说：**在这个位置点下去，会点到描述说的那个东西吗？**

判完填 `is_same`：会 → `yes`，不会 → `no`。

## 图里有什么

图是以候选位置为中心从屏幕上裁下来的。

- **十字星**：红色细十字，四条臂从中心向四周伸出。**交点就是交付的坐标 —— 唯一要看的东西。**

**乙 = 十字交点压住的那个元素或区域。**

## 步骤

### 第一步：只看图，确定乙

**先不要读最后那段目标描述。** 只看图，回答：

- **交点落在哪个元素上？**（看图一 —— 那里目标最大最清楚）
- **画面里有没有行号 / 列号 / 序号？** 表格、列表、网格这类界面会带编号，按钮、菜单、图标通常没有。有的话它在第几个 —— 从可见序列的第一个数起，**紧贴画面边缘的那个也算第一个**；没有就写「无索引」。
- **它上面有什么文字、数字、图标？**（看图一）
- **它什么颜色？**（看图一）
- **它四周紧邻的是什么？**（图一近处、图二远处）

**交点可能落在两格的边界线上。** 这时看它偏向哪一侧 —— 交点本身只在一个元素里。

**这是你独立读出来的，后面不能因为描述而改动它。**

**界面没有编号是常态，不是缺陷。** 按钮、菜单、图标、输入框本来就没有行号列号。这时跳过索引，用文字、图标、锚点定位 —— **不要因为找不到索引就判 `no`**。

**但描述里提到了编号、图上却看不到那些标时**，说明标被裁出画面了。这时写「标尺不可见」，**不要用画面内容反推**。

### 第二步：读描述，确定甲

现在读最后那段目标描述。它说的那个元素或区域就是甲。

**描述里的每一项，都是甲的特征：**

| 特征 | 例子 |
|---|---|
| **索引** | 第几行第几列、第几个、编号（**只有界面本身带编号时才有**） |
| **文字 / 数字** | 「带数字 7 的格子」「确定按钮」 |
| **图标 / 形状** | 「齿轮图标」「圆角按键」 |
| **颜色** | 「蓝色数字」「高亮格」 |
| **锚点** | 「在 X 右边」「在 Y 上面」 |

**锚点只是相对位置，不是索引。** 它依赖别的元素（X、Y），那些元素本身认错了，锚点就跟着错。

**索引的编号就是标签上的符号本身。** 列标写 9 就是第 9 列，行标写 H 就是第 8 行。**不做任何偏移换算。** 描述里没有的换算规则（「从 0 开始计」「差一格」）一律不许自己加。

**这条只在界面本身带编号时适用**（表格、列表、网格）。按钮、菜单、图标没有编号，跳过索引这一项。

## 输出

调用 `report` 工具，不要把内容写成正文 —— 正文里说的话下游读不到。

| 字段 | 含义 | 作用 | 判定标准 |
|---|---|---|---|
**判 `yes` / `no` 只看可用判据。** 文字、图标这些在甲和乙身上都读得出来的，全一致 → `yes`；任一项不一致 → `no`。索引只有界面本身带编号时才算可用判据。
| **`remark`** | 五项对比的逐项记录 | 判 `no` 时下游据此决定往哪挪 | 每项一行，写清甲是什么、乙是什么、是否一致 |

**五项对比怎么做** —— 逐项比甲和乙，每项只回答**一致 / 不一致**：

| 对比项 | 甲 | 乙 | 分量 |
|---|---|---|---|
| 索引 | 描述说第几行第几列 / 第几个 | 从图上读出 | **界面本身带编号时才用**；无编号则整项跳过，不参与判定 |
| 文字 | 描述说什么文字 / 数字 | 乙上面有什么 | **决定性** |
| 图标 | 描述说是什么形状 | 乙是什么轮廓 | **决定性** |
| 颜色 | 描述说什么颜色 | 乙什么颜色 | 参考 —— 状态色会变，不一致不影响结论 |
| 锚点 | 描述说相对别的元素在哪 | 乙四周有什么 | 参考 —— 只在前面无法唯一确定时用它区分 |

**「可用判据」= 这一项在甲和乙身上都读得出来的。** 判 `yes` / `no` 只看可用判据���不可用的项不算一致也不算不一致。

**「看起来靠近边线」不是「压在线上」。** 三项一致、交点落在目标内部、四周还有余量时判 `yes`，不要因为不够居中就判 no。

**宁可判 no 也不要猜。** 判 no 只会让定位环节重跑一次，判错的 yes 会直接交付一个错误的点击。

### `remark` 的格式

**写结论，不要逐项复述对比过程** —— 五项怎么比是你内部的事，写出来下游也只读结论。

```
结论：交点在 <乙的位置>，描述要 <甲的位置> —— 一致 / 不一致（差在哪）
```

判 `no` 时**必须说清差在哪**，下游要用它决定往哪挪：

```
结论：交点在 B8，描述要 B9 —— 索引不一致，差一列，需要右移一格
结论：交点在「Pointer官网…升级」这一行，描述要难度列表的「简单」按钮 —— 文字不一致，压到了侧边栏
```

判 `yes` 时写清两边位置，让下游能核对：

```
结论：交点在 B8，描述要 B8 —— 一致
```

**索引读不出就写「无索引」** —— 不要编一个数字，也不要因此判 `no`。判 `no` 要有具体的不一致项：文字不符、图标不符、或交点落在目标外面。
