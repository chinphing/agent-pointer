# 渲染性能 HUD

开发用叠加层，快捷键 Cmd/Ctrl+Shift+Alt+P。界面文案保持这组数字，不写进给用户的句子。

## 不要在快照节拍上强制布局

快照是 4 Hz。下面两次读取都会迫使 WebKit 排整段消息列表；长会话上一次大约 1 秒：

- 滚动容器的 `scrollHeight`
- 每个可见行的 `offsetHeight`（行高偏差）

如果每个快照都读，主线程就只剩这一次布局：空闲时帧间隔也是约 1 秒，按键的 0ms 标记如果刚好在这个窗口里关掉，HUD 会把空窗记到 `composerDraftFlush` 一类名字上。

约定：

- 虚拟列表的 JS 计数（总高、范围、已测量行数）可以跟每个快照走，它们不碰 DOM。
- `scrollHeight` 和行高读取走 `createLayoutSampleGate`。快的读取最多 5 秒一次。一次超过 32ms 就在这次 HUD 会话里不再读，并打一条 warn。
- 输入延迟探针只记草稿长度。不要在已经迟到的那一帧再读输入框的 `scrollHeight` / `clientHeight`，否则会再强制布局一次，并记到 `composerResize` 上。

## 删掉最后一个字

macOS 输入法在输入框变空时，会从光标往前找词界。输入框如果在消息列表同一个文档里，空控件没有文本节点，这次查找会把整篇会话走一遍（大约 1 秒，提交图层时再走一遍）。

输入框放在同域 frame 里，frame 的文档在输入框处结束。不要为了样式方便把 `<textarea>` 挪回主文档。

App 与 Web 同一套。
