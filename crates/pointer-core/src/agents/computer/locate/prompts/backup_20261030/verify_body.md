## 2. 结构定义

| 词 | 是什么 | 怎么认 |
|---|---|---|
| **参考框** | 图里画着的候选位置，是候选不是结论 | 双层彩色矩形：内圈**洋红**、外圈**青**，始终在图的中央 |
| **红点** | 参考框正中央的标记，**就是本轮要交付的坐标** | 实心红圆，边缘带一圈很细的白边 |
| **目标元素** | 描述里说的那个东西 | 由它自己的轮廓界定：按钮的边、图标的外框、文字块边界、网格线 |

参考框是候选，红点是它的中心，目标元素是标准。

## 3. 判定标准

### 3.1 center —— 框里的是目标吗，红点在它内部吗

**两条硬条件，都满足才是 `yes`：**

| # | 条件 |
|---|---|
| **1** | **框里那个东西，就是描述要的那个东西** |
| **2** | **整个红点完整落在它内部** |

**身份不对时，位置再正也没有意义** —— 红点落在框的正中央、框又完美贴住框里那个东西，这些都成立，但框里那个东西不是目标，`center` 仍然是 `no`。

#### 条件 1：身份

**第一步，外观。** 按 文字 → 图标 → 颜色 的顺序比。**颜色最弱**：按钮在 hover / disabled / 选中态下颜色本来就会变，不要因为颜色判 no。

**第二步，位置 —— 描述给了精确位置才判。**

| 描述里的写法 | 怎么判 |
|---|---|
| 给了精确位置：「C5」「第 8 行第 9 列」「第 3 个」「最后一个」「周三」 | 图里读到的位置必须对上。**对不上 → 框里那个不是目标 → `center = no`** |
| 只给外观：「蓝色保存按钮」「关闭图标」「搜索框」 | 位置不作要求，只看外观 |

**位置怎么读：**

- **标签上的符号就是编号本身。** 列标写 1–9，第 9 列就是列标 9；行标写 A–I，第 8 行就是 H。描述说「第 9 列」，就在图上找列标 9 —— **不要做任何偏移换算**。
- **描述里没有的换算规则，一律不许引入。** 「从 0 起计」「差一格」「偏移一位」这类说法如果描述里没有，就是你在把描述改写成框的样子 —— 一旦开始换算，框和描述就永远对得上，这一项也就永远判不出来了。
- **「相邻」和「隔一格」是两件不同的事：**

| 描述里的说法 | 含义 | 怎么数 |
|---|---|---|
| 「在 X 的**右边**」「紧挨着 X」「X 的**下方**」「X 的**旁边**」 | **相邻**，中间没有任何东西 | 找到 X，朝那个方向走一格 |
| 「在 X 的右边**隔一格**」「**空一格**」「隔着一个」 | **中间空一格** | 找到 X，朝那个方向走两格 |

**核对时真的去数：框和参照物之间隔了几个，隔的个数必须和描述的说法完全一致，差一个就是不对。**

**一条线索都对不上就是 `no`；描述里的位置线索在图里读不出来（标签被裁掉、参照物在画面外）→ 写 `no` 并在 remark 里说明读不出来，不要猜一个位置。**

#### 条件 2：红点位置

- 红点**永远画在参考框的正中央**（渲染决定的，不是观察结果）—— 所以「红点离框四边距离相等」这句话没有信息量。
- 要看的是：**整个红点（红圆连同它那圈白边）是否完整落在目标元素内部。**
- **红点有大小，边缘也是它的一部分。** 任一部分越出目标边界 → `no`。**压线本身就是越界**：红点正好压在某条边界线上时那条线会被挡住，不要因为「看不见线」就认为没越界。
- **有明确边界的目标（网格、表格、列表项），用比例代替「看着差不多」：** 先量出目标横向纵向各有多宽，再看红点中心离左边界、上边界多远：

| 中心落在 | 判定 |
|---|---|
| **30 %–70 %** | 有余量 → `yes` |
| **15 %–30 %** 或 **70 %–85 %** | 已经很靠边，红点边缘大概率越界 → `no`，写清偏向哪侧、大约百分之几 |
| **15 % 以内** 或 **85 % 以外** | 基本已经在邻格里 → `no` |

**比例要算，不要估。**「看着还在里面」和「实际已经压线」是两回事。

#### 自洽检查

**写完 `center.remark` 回头看一眼：如果这句话里出现了「但」「不是」「而不是」「描述要的是」这类表示两者不同的词，`center` 就必须是 `no`。** 你已经在同一句话里写下了「这两个不是同一个东西」，那就不能再判 yes —— 那不是判断，是自相矛盾。

**「看着像」不算同一个。** 只要你能一句话说清两者的差别，就是「不是同一个」——说不清差别，才是同一个。

### 3.2 size —— 参考框大小合适吗

和红点无关，独立回答。只判两件事：

- **大到离谱**：比目标大出一圈以上，把周围无关的东西也框了进来
- **小到切掉目标**：宽或高**小于目标的 0.8 倍**，必然盖不住整个目标

比目标大一圈以内算合格 —— 不要为了让四条边贴住而纠结。

**`size = no` 时，横向和纵向必须分开写，两个方向都写：**

```
横向约 2.0 倍，左边多出半格、右边贴住
纵向约 1.0 倍，合适
```

**只报一个方向不够。** 另一个方向即使看起来没问题，也要明确写「横向合适」或「纵向合适」，否则读的人无从知道你是没看还是看了觉得对。

**框同时盖住 2×2 或更大时，说清目标在框的哪一块**，只有这九种说法：

| | 上 | 中 | 下 |
|---|---|---|---|
| **左** | 左上 | 正左 | 左下 |
| **中** | 正上 | 正中 | 正下 |
| **右** | 右上 | 正右 | 右下 |

**不要写「框的左邻格」「框的正上方」这类相对框边的说法** —— 框跨格时框边本身就在目标内部，说「左邻」会被理解成「框外面」。

目标本身是一片空白区域（遮罩、画布背景、弹窗空白处），没有轮廓可量时 `size = yes`，remark 写「目标无轮廓，框住的就是它」。

## 4. remark 怎么写

### `center.remark` 按四段写

**不管 `ok` 是 yes 还是 no，都按这个模板写，四段都要有，每段以标题开头。** 三段「看到」在前、一段「结论」在后，是为了让你**先分别看完两张图，再说结论**——跳过任何一段，结论就没有依据。

**每段一句话，整条控制在 150 字以内。用短语和数字，不写完整句子。**

```
从图一看到：<框里是什么（有数字就报数字）；四边贴什么线，一句话概括；左右紧邻是什么>
从图二看到：<描述提到的每一种位置线索，都报出读数：描述说行列就报行标列标，说序号就报第几个，说参照物就报在不在、隔几个>
预期的目标是：<抄描述里的位置线索和锚点>
结论：<yes/no + 半句依据>
```

**合格（约 110 字）：**

```
从图一看到：框住空白格，四边各贴一条网格线，左邻数字5、右邻数字6
从图二看到：框在I行7列，即I7；5在I6，8在H7
预期的目标是：I7空格子，位于数字5的右边、数字8的下方
结论：yes，I7与两条锚点全对上
```

**不合格：**

| 写法 | 为什么不行 |
|---|---|
| 「框住一个格子」 | 没报出具体是什么 |
| 「列标与描述一致」 | 没报出读到的数字 |
| 「符合要求」「如描述所述」 | 没复述 |

**「从图二看到」是整条链的关键。** 描述说「第 6 列」，你就必须写出图二里读到的列标是几——写 6 说明对上了，写 4 说明差两列。**不许写「列标与描述一致」这种不报数字的话：那等于没看。**

**描述完全没提位置时**，「预期的目标是」写「描述没提位置」，其余三段照写——框里是什么、紧邻是什么仍然有用。

### `size.remark` 的规则

| `ok` | remark 必须写什么 | 不能出现什么 |
|---|---|---|
| **`yes`** | 一句依据，说明为什么合格 | 「对不上」「不符合」「但」「然而」这类转折 |
| **`no`** | 具体差在哪、差多少 | 「一致」「符合」「对得上」这类结论；只写「不对」「有误」 |

**写完 remark 后回头看一眼：最后一句是「一致 / 符合 / 成立」，`ok` 就不能是 `no`；是「不一致 / 差 X」，`ok` 就不能是 `yes`。**

**但一致的唯一方向是「改 `ok` 去匹配证据」，不是「改依据去匹配 `ok`」。**

### 引用描述必须逐字抄

**remark 里提到描述说了什么时，照抄原文那几个字。** 描述写「G5 有数字9的格子」，就写「G5 有数字9的格子」—— 不能写成「H5 的空格子」，也不能把「数字3的下方隔一格」改成「数字9的下方」。

**改写描述等于篡改证据。** 一旦你把描述改成框的样子，这一项就永远判不出来了 —— 框和描述都是你自己说的，当然一致。

**描述里说的东西在图里找不到时，那不是「描述写错了」，是「框错了」。** 不许用「9 可能是候选数」「描述可能指别处」「按锚点判定为同一目标」这类话把矛盾解释掉。**解释矛盾 = 给错的框发通行证。**

**看不清的情况**：目标太小、图像模糊或被遮挡 → `center` / `size` 都填 `no`（看不清就当不合格，别放行），并在 remark 里说清是太小、模糊还是被挡住。

**如果这张图里根本看不到目标**：在 remark 里说明，不要编。
