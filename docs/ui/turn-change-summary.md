# 轮次修改摘要（挂在 turn 页脚）

把文件变更从输入框上方挪到**每一轮对话结尾**。
视觉上跟「工作耗时」同一层级：过程备注，不是第二条助手气泡。

基线存储与 Review API 见
[`../developer/turn-file-baseline-review.md`](../developer/turn-file-baseline-review.md)。

## 位置

每个 user-anchored turn（`turn.id` = lead 用户消息 id）页脚，顺序固定：

1. 用户问题
2. 过程 / 任务板 / 助手回复（可折叠）
3. 耗时条（有隐藏过程时）
4. **修改摘要**（该轮有成功写文件才出现）
5. 下一轮用户消息

过程折叠时摘要仍在。输入框上方不再挂「本轮修改」。

挂在 `MessageList` 虚拟行内部，和消息同一 `.chat-column`。
不要贴 Composer，不要做成助手气泡。
不要重排用户问题、过程、任务板、助手回复或耗时条；
只在该轮现有内容后面挂载摘要。

## 外观

与助手正文同一 `px-3` 左边距，左缘对齐「测试要点」等正文。
卡片随内容变宽，最大不超过对话列（`px-3` 内 100%），不再限制 22rem。
多文件时收缩与展开同宽（隐藏测宽行按最长路径，列表本身不横向滚动）。
路径或文件名超出时左侧省略号，优先露出右侧文件名（全局 `.ellipsis-start`，工具行文件路径同一套）。
圆角 `rounded-lg`、细描边、无阴影、`bg-card` 浅底（与对话背景区分）。

**标题行**

- 高约 34px，左右内边距 12px
- 左：文件图标 + `修改了 N 个文件`（13px，`text-muted`）+ 合计 `+n`（有删除才跟 `-n`）
- 右：chevron（展开旋转 180°）

**仅 1 个文件**

- 文案：`修改了 Login.vue` + 合计 `+/-`
- 点击标题打开该轮 diff，不展开列表

**2 个文件**

- 默认展开列表；用户收起后本会话内记住

**文件列表（展开）**

- 与标题之间 1px 分隔；行与行之间同样分隔
- 左：相对路径（11px mono，超出时左侧 `…`）；右：该文件 `+n`（有删除才跟 `-n`）
- 行高约 34px；超过 6 个文件再滚，最多约 12rem
- 点击行打开该轮该文件的 Review
- 3 个及以上文件默认收起，点标题展开

进行中：文案仍是 `修改了 N 个文件`，N 随成功写入增加，不写「正在修改」。

无成功 `file_edit` / `file_write`：整块不渲染。

## 交互

| 操作 | 行为 |
|------|------|
| 点标题（多文件） | 只展开列表，不打开工作区 |
| 点文件行 / 单文件标题 | `openTurnDiff({ conversationId, turnId, path })` |
| 展开列表 | 该虚拟行 `resizeTurnRow`，避免重叠 |
| 无工作区 | 不打开；debug 打 warn |

展开状态按 `turnId` 记在 `MessageList` 内存，不落盘。切会话清空。

## 数据

- 列表：该轮成功写文件工具，按路径去重。来源包括消息自己的 `toolCalls`、scoped 子消息，以及仍写在 `agentTrace.session.toolCalls` 上的子 Agent 工具（无 scoped 子行时的实时路径）。
  窗口里整份 scoped 表不能直接并进最新一轮：只收 `anchorMessageId` 落在该轮切片里的子行（含锚在另一条子行上的嵌套 spawn）。否则上一轮的「修改了 N 个文件」会在新问题下面再出现一次。
- 当前轮：每条成功的 `file_edit` / `file_write` 立刻进卡片，不必等同一条助手消息上后续的搜索/阅读结束。
  顶层 Agent 会在同一条消息上持续追加工具；若等整批离开 running，过程中摘要会一直空白。
  打开本轮或换轮时扫一次切片做底账；之后只合并新出现的写入工具（按路径累加 `+/-`）。
  轮次边界与消息列表相同：真实用户任务（不含 scoped 子消息、空回复重试注入）。
  已结束轮次冻结；新开一轮只快照刚结束的那一轮，更早轮复用原数组。
- `+/-`：该轮工具结果统计；`file_write` 同样带 `stats`（新建多为 `+n`，`dels` 为 0 时不显示 `-n`）
- 打开 Review：左侧 = 本轮基线；右侧 = **之后同一路径的下一份基线**，没有则对比磁盘
- 查找：只 `exists` 后续有基线的轮次目录，命中即停，不扫对话正文

列表能随消息持久化看到。历史轮打开 diff 时，右侧不再被**同一会话**更后面的手改/再编辑拖走（该会话最后一次改该文件的轮次仍对比磁盘）。

跨会话改同一工作区文件时的干扰见
[`../developer/turn-file-baseline-review.md`](../developer/turn-file-baseline-review.md)「已知问题」。

## 文案

| 场景 | 文案 |
|------|------|
| 多文件收起 | 修改了 N 个文件 +n -n |
| 单文件 | 修改了 {文件名} |
| Review Tab | 文件名；副标题不写「本轮」 |
| 基线缺失 | 沿用现有 Review 空态，摘要列表仍显示 |

不要用「本轮修改」（挂在历史轮会歧义）。

## 跨端

桌面 / Web 同一组件。移动端同样页脚一行，展开列表不要撑破对话列。

## 不做

- 不在输入框上方再留最新一轮副本
- 不和右侧 Git「变更文件」合并
- 不在每轮结束再存一份全文（用下一轮同路径基线当「改完」）
- 跨会话改同一工作区文件时，历史 Review 右侧可能被磁盘拖走（先记着，见基线文档「已知问题」）
