# 定位任务

请找出界面中符合以下描述的元素，给出它的位置。

## 1. 目标元素描述

· 目标：{desc}

{near}
## 2. 坐标要求

只按「这张图」给坐标：横向 0 = 这张图左边缘，1000 = 右边缘；纵向 0 = 上边缘，1000 = 下边缘。不需要知道整张屏幕有多大。

## 3. 两种框：参考框和目标框

**这一节定义两个词，后面全用这两个名字，不用颜色指代。**

### 参考框

**图里已经画着的一个矩形，框线是一圈细实线，四条边围成一块区域；它的正中央画着一个红点（实心红圆，边缘带一圈很细的白边）。**

**参考框是候选位置，不是目标本身，也不是你要输出的东西。** 红点是它的中心，也就是上一轮要交付的坐标。

**参考框永远画在这张图的正中央** —— 裁剪时就是以它为中心截的，四周留了余量。所以「参考框在图的中间」这件事**没有任何信息量**，不代表它是对的。真正的目标可能在正中，也可能偏在一侧，甚至只有一部分在图里。

第一轮时参考框来自调用方的估计，可能偏；后续轮次它是上一轮的结果。

### 目标框

**你要输出的那个矩形。** 按目标元素本身重新确定四条边在哪，和参考框对不对无关。

**参考框只是一个起点，不是标准答案** —— 第一轮它来自调用方的估计，后续轮次它是上一轮的结果，两种都可能偏。**不要靠放大或缩小参考框来凑 —— 目标框是按目标元素重新确定的。**

### 两者的关系

| | 参考框 | 目标框 |
|---|---|---|
| 在图里吗 | **画着，能看见** | **看不见，要你算出来** |
| 谁给的 | 调用方的估计，或上一轮的结果 | 你按目标元素的四条边确定 |
| 会偏吗 | **会**，第一轮尤其偏 | 应该贴着目标元素 |
| 你输出什么 | 不输出 | **输出它的四条边坐标** |

## 4. 目标框的大小

**先认准四条边，再给坐标。** 在写 bbox 之前，先在脑子里把目标元素自己的四条边找出来：

- 左边线在哪？是哪一条可见的边界（网格线、控件外框、文字块的起笔、图标的轮廓）？
- 右边线、上边线、下边线同理。

四条边都认准了，再把这四条线的位置换算成坐标。**不要先估一个框的大小再往里填数字** —— 那样得到的是「看起来差不多大」的框，不是「四条边都落在目标轮廓上」的框。

**目标框的四条边，各贴着目标元素对应的那条边。** 一条一条对：

- 框的边在目标轮廓**外面**（能看到框和目标之间有空隙）→ 框太大
- 框的边**切进**目标内部（目标有一部分在框外）→ 框太小
- 框的边和目标轮廓**在同一条线上** → 这条边合格

四条边都在同一条线上才算合格。

**不要「先包住再收回」。** 那个说法会让人以为「包住」是第一目标、「收回」是附带的 —— 实际两个方向都不合格，唯一合格的状态是四条边贴住。宽高也不要超过目标的 {size_max} 倍。

**不要为了让目标「完全在框内」而留余量。** 贴着轮廓时目标自然完全在框内；留出来的余量只会让框的中心偏离目标的中心 —— 比目标大一倍时，目标框的中心会落在两个相邻元素的分界线上，返回的坐标就偏到隔壁去了。

关键是**目标框的中心点要落在目标元素上**——目标框明显偏向一侧、或者中心跑到目标外面，返回的坐标就会偏。

不需要像素级精确：四条边没有明显偏离轮廓，就算合格。

## 5. 锚点不是目标

描述里提到的其他元素（「在 X 的右边」「X 的左边」「X 的下方」「旁边有个 Z」「隔一格」）是用来确认目标位置的**参照物，不是要框的东西**。目标框只包住目标本身。目标紧挨着参照物时，目标框的边界正好落在两者之间的分隔线上——不要为了「把参照物也带上」而放大。把参照物框进来，目标框的中心就移到两者之间，返回的坐标也就偏了。

## 6. 上一轮的情况怎么用

「上一轮的情况」是上一轮校验的结论，写了哪个维度不合格、看到了什么。**按它说的改，不要整框重画** —— 重画会把上一轮对的部分也丢掉：

- 大小不合适 → 上一轮会分别写横向和纵向，还会用**九宫格**说目标在参考框的哪一块（左上 / 正上 / 右上 / 正左 / 正中 / 正右 / 左下 / 正下 / 右下）。**两个方向都要看，都要改** —— 只改它说「明显超了」的那一个方向，另一个方向原样留着，框的中心还是会偏。改的时候**一条边一条边改**：可能只有一条边超了，其余三条是准的，整体缩放会把准的那三条也弄偏。上一轮如果某个方向写了「合适」，那个方向就别动。
- **九宫格只给大概位置，不是答案。** 上一轮说「目标在参考框的左下」，意思是「把参考框切成九块，目标在左下那一块里」—— 你要做的**是去那一块里找目标、按目标自己的轮廓定四条边**，不是直接把那一块的四条边当结果。那一块只是缩小了搜索范围。
- 中心偏了 → 把目标框的中心移到目标元素上，大小别动。
- **位置不对 → 不要移动参考框，重新定位。** 参考框不在位置标识说的那一格，说明它一开始就错了 —— 沿着它平移只会沿着错误的方向走。**忘掉参考框的位置，只按描述重新找：** 先读出描述里的位置标识（第几行第几列、第几项），在图里找到那一格；再用锚点确认；两样都对上了，按那一格的轮廓定四条边。

**位置不对和大小不对是两回事，处理方式不同：**

| 上一轮说 | 怎么做 |
|---|---|
| 大小不对 | **参考框的位置是对的**，只在原位置上改边 —— 逐条边挪 |
| 位置不对 | **参考框的位置是错的**，不要在它基础上挪 —— 按描述从零找 |

**不要用「平移参考框」来修位置。** 参考框错了可能错半格、错一格、错两格，上一轮说的「差几格」也可能读错 —— 平移的结果是错上加错。**按位置标识重新找是绝对定位，不依赖上一轮说了什么。**

**纵向和横向是两件独立的事。** 纵向对了、横向错了是常事，反之亦然。**上一轮只提了一个方向时，另一个方向要自己看一眼再决定动没动** —— 它没提不等于那个方向是对的，可能只是没看到。

## 7. 目标不在这张图里时

**这张图是从屏幕上裁下来的一块，可能根本不含目标。** 这时填 `found = false`，**不要给 bbox**。

**怎么判断「不在这张图里」：**

| 情况 | `found` |
|---|---|
| 目标在画面里，位置清楚 | `true` + 精确 bbox |
| 目标在画面里，但边界看不清、只能给个大概 | **`true`** + 大致 bbox —— 下一轮会修 |
| **画面里完全找不到目标**（描述里的东西一个都不在） | **`false`**，不给 bbox |
| 只有目标的一部分在画面边缘 | **`true`** + 大致 bbox —— 至少知道方向 |

**瞎框一个比说「不在」更糟。** 调用方拿到 bbox 就会当成答案交付；拿到 `found = false` 会换一张范围更大的图再找。**前者把错误送到用户手里，后者只是多花一次调用。**

**「不在这张图里」和「看不清」是两件事。** 目标就在眼前但边界模糊 —— 填 `true` 给个大概框，不要说找不到。**只有真的找不到才填 `false`。**
