### locate_element

把「描述」变成「坐标」。**不点击、不输入、不改变桌面状态** —— 它只回答
目标在当前截图里的位置。

**输入**

```json
{"elements": [
  {"description": "地址栏右侧的刷新按钮"},
  {"description": "『文件』菜单里的『另存为』", "hint_box": [800, 35, 840, 55]}
]}
```

- 单个 `elements` 数组，每项一个 `description`，可选一个 `hint_box`。
- **最多 3 项**。超过 3 项直接报参数错误；请拆成多次调用。
- `hint_box` 是 4 个**逻辑像素**值 `[x1, y1, x2, y2]`，是你对目标的初步估计，
  **不是最终点击坐标**。只有当你确实看到目标大致在哪时才传。

**输出**

```json
{"results": [
  {"status": "located",
   "summary": "已找到「地址栏右侧的刷新按钮」并确认位置，坐标 (820, 45) 是元素中心，可直接用于点击。",
   "description": "地址栏右侧的刷新按钮", "x": 820, "y": 45,
   "confidence": "high", "what_i_saw": "圆形箭头图标"},
  {"status": "not_found",
   "summary": "没有在当前画面找到「『文件』菜单里的『另存为』」。不要用猜测的坐标点击；先滚动、切换页面或等待加载，再重新定位。",
   "description": "『文件』菜单里的『另存为』", "what_i_saw": "当前截图中未能可靠确认目标"}
]}
```

**`status` 一个字段说清结果**：

| `status` | 含义 | 下一步 |
| --- | --- | --- |
| `located` | 找到了，`x` / `y` 是准确位置 | 直接用 `x` / `y` 点击，**不要再定位一次** |
| `not_found` | 当前画面里没有 | 先滚动 / 切换页面 / 等加载，再重新定位 |
| `not_verified` | 候选框没通过校验 | 换更有区分度的描述（加锚点、加文字） |
| `unclear` | 画面太糊或被遮挡 | 先让界面稳定（等加载、关弹窗） |

`summary` 是同一件事的自然语言版本，带坐标或下一步动作。

**`x` / `y` 是唯一要用的坐标**

- `x` / `y` 是定位框的中心点，**落在元素内部**就能点中。
- `confidence` 是可信度：
  - `high` — 已确认是目标，直接用
  - `medium` — 大概率对，周边可能有干扰
  - `low` — 建议换个描述重试

**看到 `located` 就直接执行**

`located` 加上 `confidence: high` 已经足够：目标确认、坐标可点。
重复定位会拿到略微不同的坐标（视觉模型有随机性），那不是「更准」，
只是抖动。**除非界面明显变了，否则不要再调。**

**什么时候不用它**

- 用户明确给出了坐标。
- 坐标来自刚才某次 `locate_element` 的成功结果，且界面没有变化。
